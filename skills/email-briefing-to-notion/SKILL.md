|------|----|

## 0. 실행 시 먼저 KST 날짜 확인

get_current_korean_time를 실행하여 한국 날짜를 확인한다.
검색 및 실행 기준은 'get_current_korean_time'기준으로 진행.

확인되었으면 Step 0-1로 진행.

## 0-1. 월요일 주간 요약 분기

get_current_korean_time으로 확인한 요일이 **월요일**이면 아래 주간 요약 흐름을 먼저 실행한다.
월요일이 아니면 즉시 Step 1로 건너뛴다. **휴무일이어도 강제 실행한다.**

### 주차 계산
- 지난주 범위: 당일(월요일) 기준 -7일(전주 월요일) ~ -1일(전주 일요일)
- 페이지 제목: `MM월 N주차 이메일 요약`
  - N주차 = 해당 월에서 몇 번째 월요일인지 기준 (첫 번째 월요일 포함 주 = 1주차)
  - 예: 지난주가 6월 첫째 주 → `6월 1주차 이메일 요약`
  - 월 경계를 넘는 경우(예: 지난주 월요일이 5월, 일요일이 6월) → 지난주 월요일의 월 기준

### 중복 확인
Notion 상위 페이지 하위에 동일 제목(`MM월 N주차 이메일 요약`)이 이미 존재하면:
- 새 페이지를 만들지 않는다
- 기존 페이지 하단에 `--- 추가 갱신 (HH:MM) ---` 섹션으로 append

존재하지 않으면 아래 지난주 페이지 수집으로 진행.

### 지난주 일일 페이지 수집
- Notion 상위 페이지(`3643e986-a942-812e-b4e9-dca08f857e86`) 하위 페이지 목록 조회
- 제목 패턴 `YYYY.MM.DD (요일)` 중 지난주 7일(월~일)에 해당하는 페이지를 수집
- 각 페이지를 `notion-fetch`로 읽어 P1~P4 건수 및 액션 아이템 추출
- 페이지가 없는 날짜는 `-` 표시

### 주간 요약 페이지 생성
- **위치**: 상위 페이지 `3643e986-a942-812e-b4e9-dca08f857e86` 하위
- **제목**: `MM월 N주차 이메일 요약`
- **아이콘**: 📊

#### 본문 템플릿

```
## 📊 주간 요약 — MM월 N주차 (MM/DD ~ MM/DD)

| 날짜 | P1 | P2 | P3 | P4 | 합계 |
|------|----|----|----|----|------|
| MM/DD (월) | N | N | N | N | N |
| MM/DD (화) | N | N | N | N | N |
| MM/DD (수) | N | N | N | N | N |
| MM/DD (목) | N | N | N | N | N |
| MM/DD (금) | N | N | N | N | N |
| MM/DD (토) | N | N | N | N | N |
| MM/DD (일) | N | N | N | N | N |
| **합계** | **N** | **N** | **N** | **N** | **N** |

---

## 🔴 주요 P1·P2 이슈 요약

| 날짜 | 제목 | 액션 아이템 요약 |
|------|------|-----------------|
| MM/DD | [제목] | [처리 내용 또는 미처리] |

---

## 📌 주간 주요 키워드

[지난주 P1·P2에서 반복 등장한 장비명·현장코드·업무 키워드 3~5개]

---

@한이현
🤖 자동 작성 by Claude Code, YYYY.MM.DD (월) 주간 요약
```

**규칙**
- 지난주 P1·P2가 0건이면 `🔴 주요 P1·P2 이슈 요약` 섹션 생략
- 일일 브리핑 페이지가 없는 날짜는 해당 행에 `-` 표시
- ⚠️ 일부 일일 페이지 누락 시 페이지 최상단에 표기: `⚠️ 지난주 N건 중 M건만 조회됨`

### 주간 요약 완료 후
주간 요약 페이지 생성이 완료되면 Step 1로 진행하여 **오늘(월요일) 일일 브리핑도 함께 실행**한다.

### 주간 요약 오류 처리

| 상황 | 동작 |
|------|------|
| 지난주 일일 페이지 0건 | 주간 요약 미생성, Step 1로 진행 |
| 일부 일일 페이지 누락 | 조회된 페이지만으로 요약, 상단 ⚠️ 표시 |
| 이미 주간 요약 존재 | 새 페이지 미생성, 기존 페이지 하단 append |
| Notion 조회 실패 | 주간 요약 건너뛰고 Step 1 진행 |

---

## 1. 중복 확인

Notion 상위 페이지 하위에 `today_` 제목 페이지가 이미 존재하면:
- 새 페이지를 만들지 않는다
- 기존 페이지 하단에 `--- 추가 브리핑 (HH:MM ) ---` 섹션으로 append
- 전날 노션 페이지를 확인하여 이어지는 내용이 있으면 연관 표시를 한다.

존재하지 않으면 Step 2로 진행.

## 2. Gmail 이메일 수집

### 검색 쿼리
```
in:inbox -is:spam -in:draft -in:sent -label:[Notion]
after:yesterday_ before:today_
```
- pageSize: 50
- `-label:[Notion]` = 이미 처리된 이메일 제외

### 조회 전략 (토큰 절약)
1. `search_threads` — 제목·발신자·스니펫 전체 수집
2. 스니펫+제목으로 1차 분류 (Step 3)
3. **P1·P2만** `get_thread`로 본문 전체 조회
4. P3·P4는 스니펫+제목으로만 요약

### 컨텍스트 초과 시
P1 → P2 → P3 → P4 순으로 우선 처리하고, Notion 페이지 최상단에 표기:
```
⚠️ 컨텍스트 제한 — 총 N건 중 M건만 처리됨
```

## 3. 이메일 분류

모호한 경우 더 높은 우선순위로 분류한다.

### 🔴 P1 — 긴급 사항 (Critical)
- TO에 `han@solardin.com`, `한이현` 직접 포함
- 키워드: 요청, 확인 부탁, 검토 부탁, 긴급, 승인, 마감, 결정, 회신 요청, 한이현, 기구설계팀
- 예외: 전체 공지사항
- 4M 변경 승인, 결재 요청 문서

> 예: `MPT 파트리스트 수정 요청 건` / `Amkor Technology 긴급 Swap 출하 요청` / `4M 변경 승인 요청서`

### 🟠 P2 — 중요 사항 (High)
- 현장 장비 알람·이슈 (chiller 고장, OCR Alarm 등) — 모니터링·대응 필요
- 결재 취소·반려 알림 중 재처리 필요한 것 (`_sysmaster_` 발신)
- 외주업체 납기·일정 답변 필요 건
- D-0 ~ D-1 마감

> 예: `(260525_MMJ) Comp2 inner check alarm 발생` / `[결재취소] 한이현` / `파카코리아 솔밸브 전압 마킹 답변`

### 🟡 P3 — 일반 사항 (Medium)
- 프로젝트 진행 상황·CC 참조 업무
- 현장 일일보고 중 이슈 있는 것
- 납품대장, 납기 조율, 출하 진행 상황
- 기한 있는 관리·공지 (법정의무교육 등)

> 예: `칠러납품대장_260522` / `601 공냉식 피팅 확인 요청` / `법정의무교육 기한 임박`

### 🟢 P4 — 일반 사항 (Low)
- 현장 일일보고 `(YYMMDD_현장코드)` 중 특이사항 없음·완료 보고
- 이슈 없는 일일회의록·주간업무보고
- 결재 완료 알림, 경조사·사내공지

> 예: `(260525_MMS) 특이사항 없음` / `주간업무보고 5월 3주차_정예진`

### ❌ 제외 (레이블 미부착)
업무 무관 외부 서비스: Zapier(`learn@send.zapier.com`), Slack(`no-reply@email.slackhq.com`), make.com, n8n, GamsGo, Google 보안알림(`no-reply@accounts.google.com`) 등
