## 0. 시간대 — KST 강제 적용

get_current_korean_time를 실행하여 한국 날짜를 확인한다.
검색 및 실행 기준은 'get_current_korean_time'기준으로 진행.

확인되었으면 Step 0-1로 진행.

```

| 시스템 UTC | ❌ 잘못된 날짜 | ✅ KST 날짜 (today_) |
|-----------|-------------|---------------------|
| 2026-05-25 15:30 UTC | 05/25 | **05/26** (15:30+9h = 익일 00:30) |
| 2026-05-25 00:00 UTC | 05/25 | **05/25** (00:00+9h = 당일 09:00) |
| 2026-05-24 23:00 UTC | 05/24 | **05/25** (23:00+9h = 익일 08:00) |

- **Notion 페이지 제목**: 반드시 `today_`(KST) 사용
- **Gmail 쿼리 날짜**: `after:start_date_` / `before:today_` (모두 KST 기준)

KST 날짜 확인 후 Step 0-1로 진행.

## 0-2. 월요일 주간 요약 분기

get_current_korean_time으로 확인한 요일이 **월요일**이면 아래 주간 요약 흐름을 먼저 실행한다.
월요일이 아니면 즉시 Step 0-3으로 건너뛴다.

### 이전 주 폴더 탐색

주간 요약을 넣을 이전 주 폴더를 먼저 확인한다 (Step 0-3 로직과 동일, 이전 주 기준).

- `prev_monday_` = today_(월요일) - 7일
- `prev_month_folder_title_` = `N월 이메일 브리핑` (prev_monday_ 기준 월)
- `prev_week_folder_title_` = Step 0-3 방식으로 계산 (prev_monday_ 기준)
- 루트 하위에서 `prev_month_folder_title_` 탐색 → 없으면 생성 → `prev_month_folder_id_`
- `prev_month_folder_id_` 하위에서 `prev_week_folder_title_` 탐색 → 없으면 생성 → `prev_week_folder_id_`

### 주차 계산
- 지난주 범위: `prev_monday_` ~ `prev_monday_` + 6일(전주 일요일)
- 페이지 제목: `N주차 이메일요약`
  - N주차 = `prev_week_folder_title_`의 N 값과 동일
  - 예: 지난주가 6월 첫째 주 → `1주차 이메일요약`
  - 월 경계를 넘는 경우(예: 지난주 월요일이 5월, 일요일이 6월) → prev_monday_의 월 기준 N 산정

### 중복 확인
`prev_week_folder_id_` 하위에 동일 제목(`N주차 이메일요약`)이 이미 존재하면:
- 새 페이지를 만들지 않는다
- 기존 페이지 하단에 `--- 추가 갱신 (HH:MM) ---` 섹션으로 append

존재하지 않으면 아래 지난주 페이지 수집으로 진행.

### 지난주 일일 페이지 수집
- `prev_week_folder_id_` 하위 페이지 목록 조회 (없으면 루트 하위에서도 검색)
- 제목 패턴 `YYYY.MM.DD (요일)` 중 지난주 7일(월~일)에 해당하는 페이지를 수집
- 각 페이지를 `notion-fetch`로 읽어 P1~P4 건수 및 액션 아이템 추출
- 페이지가 없는 날짜는 `-` 표시

### 주간 요약 페이지 생성
- **위치**: 이전 주 폴더(`prev_week_folder_id_`) 하위
- **제목**: `N주차 이메일요약`
- **아이콘**: 📊

#### 본문 템플릿

```
## 📊 주간 요약 — MM월 N주차 (MM/DD ~ MM/DD)

| 날짜 | P1 | P2 | P3 | P4 | 합계 |
|------|----|----|----|----|------|
| MM/DD (월) | N | N | N | N | N |
| MM/DD (화) | N | N | N | N | N |
| MM/DD (수) | N | N | N | N | N |
| MM/DD (목) | N | N | N | N | N |
| MM/DD (금) | N | N | N | N | N |
| MM/DD (토) | N | N | N | N | N |
| MM/DD (일) | N | N | N | N | N |
| **합계** | **N** | **N** | **N** | **N** | **N** |

---

## 🔴 주요 P1·P2 이슈 요약

| 날짜 | 제목 | 액션 아이템 요약 |
|------|------|-----------------|
| MM/DD | [제목] | [처리 내용 또는 미처리] |

---

## 📌 주간 주요 키워드

[지난주 P1·P2에서 반복 등장한 장비명·현장코드·업무 키워드 3~5개]

---

@한이현

**규칙**
- 지난주 P1·P2가 0건이면 `🔴 주요 P1·P2 이슈 요약` 섹션 생략
- 일일 브리핑 페이지가 없는 날짜는 해당 행에 `-` 표시
- ⚠️ 일부 일일 페이지 누락 시 페이지 최상단에 표기: `⚠️ 지난주 N건 중 M건만 조회됨`

### 주간 요약 완료 후
주간 요약 페이지 생성이 완료되면 Step 0-3으로 진행하여 **오늘(월요일) 일일 브리핑도 함께 실행**한다. (월요일은 주말 종료 대상에서 제외되므로 일일 브리핑도 정상 실행)

### 주간 요약 오류 처리

| 상황 | 동작 |
|------|------|
| 지난주 일일 페이지 0건 | 주간 요약 미생성, Step 0-3으로 진행 |
| 일부 일일 페이지 누락 | 조회된 페이지만으로 요약, 상단 ⚠️ 표시 |
| 이미 N주차 이메일요약 존재 | 새 페이지 미생성, 기존 페이지 하단 append |
| Notion 조회 실패 | 주간 요약 건너뛰고 Step 0-3 진행 |

## 0-3. 월별·주별 폴더 준비

일일 브리핑을 넣을 월 폴더와 주 폴더를 확인하고, 없으면 생성한다.

### 변수 계산

| 변수 | 계산 방법 |
|------|----------|
| `month_folder_title_` | `N월 이메일 브리핑` (today_ 기준 월, N = 월 숫자) |
| `week_monday_` | today_ 가 속한 주의 월요일. 단, 해당 월요일이 today_ 와 다른 달이면 today_ 달의 1일 |
| `week_sunday_` | 해당 주의 일요일. 단, 월말을 넘으면 해당 달의 마지막 날 |
| `week_n_` | today_ 달 기준 주 번호 (달의 1일을 포함하는 주 = 1주차, 이후 월요일마다 +1) |
| `week_folder_title_` | `N주차 (MM.DD~MM.DD)` — week_n_, week_monday_, week_sunday_ 사용 |
| `target_parent_id_` | 일일 브리핑 및 중복 확인에 사용할 주 폴더 ID |

**주차(N) 계산 예시**
- 6/1(월) → `1주차 (06.01~06.07)`
- 6/8(월) → `2주차 (06.08~06.14)`
- 6/4(목), 이 주 월요일 6/1 → `1주차 (06.01~06.07)`
- 6/3(수), 이 주 월요일 5/28(이전 달) → week_monday_=6/1로 대체 → `1주차 (06.01~06.07)`

### 월 폴더 확인·생성

1. 루트 페이지(`3643e986-a942-812e-b4e9-dca08f857e86`) notion-fetch → 하위 페이지 중 `month_folder_title_` 탐색
2. 존재하면 → `month_folder_id_` 기록
3. 없으면 → notion-create-pages (제목: `month_folder_title_`, 아이콘: 📅, 내용: `"N월 전체 이메일 브리핑 보관 공간"`, 부모: 루트) → `month_folder_id_` 기록

### 주 폴더 확인·생성

1. `month_folder_id_` notion-fetch → 하위 페이지 중 `week_folder_title_` 탐색
2. 존재하면 → `target_parent_id_` 기록
3. 없으면 → notion-create-pages (제목: `week_folder_title_`, 아이콘: 📋, 내용: `"기간 브리핑"`, 부모: `month_folder_id_`) → `target_parent_id_` 기록

주 폴더(`target_parent_id_`) 하위에 `today_` 제목 페이지가 이미 존재하면:
- 새 페이지를 만들지 않는다
- 기존 페이지 하단에 `--- 추가 브리핑 (HH:MM ) ---` 섹션으로 append
- 전날 노션 페이지를 확인하여 이어지는 내용이 있으면 연관 표시를 한다.

존재하지 않으면 Step 2로 진행.

## 2. Gmail 이메일 수집

### 검색 쿼리
```
in:inbox -is:spam -in:draft -in:sent
(label:쏠라딘 OR label:현장업무보고)
after:start_date_ before:today_
```
- `today_` = 브리핑 대상 날짜 (KST 기준, 실행일과 다를 수 있음)
- `start_date_` = 아래 날짜 범위 규칙으로 결정
- pageSize: 50
- `label:쏠라딘 OR label:현장업무보고` = 솔라딘 조직도 라벨 메일만 수집 (서비스 알림 자동 제외)
- 중복 방지: 날짜 범위가 겹치지 않도록 설계됨. 같은 날 재실행 시 Step 1 중복 확인으로 처리

### 날짜 범위 결정 규칙

**[규칙 1] 월요일 예외 (최우선 적용)**
요일이 월요일이면:
- `start_date_` = 당일(월요일) -3일인 **금요일**
- `before:today_` = **당일(월요일)** 유지 — 월요일 당일 이메일 미포함
- 단, 금요일도 휴일이면 규칙 2를 이어서 적용

**[규칙 2] 휴일 연장 (화~금, 또는 규칙 1 적용 후 추가 확장)**
`start_date_`가 휴일(토·일 또는 한국 법정 공휴일)이면:
- `start_date_`를 1일 더 앞당긴다 (→ 전전날 06:30부터 포함)
- 앞당긴 날도 휴일이면 계속 반복 → 평일에 도달할 때까지 앞당김

> 예 1) 화요일 실행, 어제(월)=공휴일 → `start_date_`=일요일 → `after:일 before:화` (일·월 이메일 포함)
> 예 2) 화요일 실행, 어제(월)=공휴일·그제(일)=일요일 → `start_date_`=토요일 → `after:토 before:화` (토·일·월 포함)
> 예 3) 월요일 실행, 지난 금요일이 공휴일 → 규칙 1로 `start_date_`=금요일 → 규칙 2로 목요일로 앞당김

### 조회 전략 (토큰 절약)
1. `search_threads` — 제목·발신자·스니펫 전체 수집
2. 스니펫+제목으로 1차 분류 (Step 3)
3. **P1·P2만** `get_thread`로 본문 전체 조회; 이전 메일(대화목록)이 있으면 히스토리 파악 후 간략 요약
4. P3(현장업무보고 외)는 맥락 파악 필요 시에만 `get_thread` 사용
5. P3(현장업무보고)·P4는 스니펫+제목으로만 요약

### 컨텍스트 초과 시
P1 → P2 → P3 → P4 순으로 우선 처리하고, Notion 페이지 최상단에 표기:
```
⚠️ 컨텍스트 제한 — 총 N건 중 M건만 처리됨
```

## 4. 이메일 분류

### 🔴 P1 — 즉시처리

다음 중 하나 이상 해당:
- **TO에 `han@solardin.com` 직접 포함** + 아래 라벨 중 하나
  - `쏠라딘/기구설계팀/*` (팀장·수석 포함)
  - `쏠라딘/대표이사/*`
  - `쏠라딘/해외기술영업팀/*` (현장 긴급 요청)

- 외부 고객사/업체 발신 (라벨 없음) + TO 직접 + 긴급 키워드

> 예: `MPT 파트리스트 수정 요청 건` / `Amkor Technology 긴급 Swap 출하 요청` / `4M 변경 승인 요청서`

### 🟠 P2 — 오늘 중 처리

다음 중 하나 이상 해당:
- **기구설계팀 관련** (`쏠라딘/기구설계팀/*`) 중 P1 미해당 (CC 참조, 정보 공유)
- 현장 장비 알람·이슈 — 모니터링·대응 필요 (`Comp2 inner check alarm`, `chiller 고장`, `OCR Alarm`)
- 결재 취소·반려 알림 중 재처리 필요한 것 (`_sysmaster_` 발신)
- `쏠라딘/구매자재팀/*` 또는 외주업체 납기·일정 답변 필요 건
- D-0 ~ D-1 마감

> 예: `(260525_MMJ) Comp2 inner check alarm 발생` / `[결재취소] 한이현` / `파카코리아 솔밸브 전압 마킹 답변`

---

### 🟡 P3 — 이번주 처리

다음 중 하나 이상 해당:
- **`현장업무보고/*`** 라벨 + 이슈·알람·조치사항 있는 것
- `쏠라딘/*` 내부 발신 중 CC 참조 업무, 프로젝트 진행 상황 공유
- `쏠라딘/품질팀/*` 납품대장, 출하 진행 상황
- 기한 있는 관리·공지 (`쏠라딘/인사팀/*` 법정의무교육 등)
- 외부 업체 납기 조율, 견적 회신 (답변 필요하지만 D-2 이상)

> 예: `칠러납품대장_260522` / `601 공냉식 피팅 확인 요청` / `법정의무교육 기한 임박`

---

### 🟢 P4 — 보관참조

다음 중 하나 이상 해당:
- **`현장업무보고/*`** 라벨 + 특이사항 없음·완료 보고
- 이슈 없는 일일회의록·주간업무보고
- 결재 완료 알림 (`_sysmaster_`, 취소·반려 아닌 것)
- 경조사·사내공지 (`쏠라딘/인사팀/*`)
- **서비스 알림**: Google, Notion, Slack, Zapier, make.com, n8n 등 외부 서비스 자동 알림

> 예: `(260525_MMS) 특이사항 없음` / `주간업무보고 5월 3주차_정예진` / `Google 계정 보안 알림`

---

## 6. Gmail 조직도 라벨 자동 적용

수집된 스레드에 올바른 조직도 라벨이 누락된 경우 보완 적용한다.  
Gmail 필터로 이미 적용된 라벨은 그대로 유지하며, 중복 적용하지 않는다.

### 처리 순서

1. 각 스레드의 현재 라벨 목록 확인
2. `쏠라딘/*` 또는 `현장업무보고/*` 하위 라벨이 없으면 발신자 이메일 기준으로 매핑하여 `label_thread` 적용
3. 발신자가 외부(비 @solardin.com)이거나 매핑 불가인 경우 → 라벨 적용 생략

### 발신자 매핑 기준 (Step 3 Gmail 라벨 구조 참조)

- `@solardin.com` 발신자 → 이름 기준으로 `쏠라딘/팀/이름` 라벨 매핑
- 제목 패턴 `(YYMMDD_현장코드)` → `현장업무보고/현장코드` 라벨 매핑
  - MMS / MMJ / MMT / CHINA

### 주의
- 이미 올바른 라벨이 있으면 건너뜀
- 주간 요약(Step 0-2) 실행 시에는 라벨 조작 금지

---

## 절대 금지

- ❌ Gmail 이메일 답장·발송
- ❌ Gmail 이메일 삭제·이동·아카이브
- ❌ 조직도 라벨(`쏠라딘/*`, `현장업무보고/*`) 외 Gmail 레이블 생성·조작
- ❌ Gmail 라벨 삭제·이름 변경
- ❌ 루트 페이지(이메일 브리핑) 계층 외부에 페이지 생성 (월·주 폴더는 루트 계층 내부이므로 허용)
- ❌ 이메일 내용 외부 시스템 전달
- ❌ 주간 요약 생성 시 Gmail 이메일 레이블 재조작 (일일 브리핑에서 이미 처리됨)
