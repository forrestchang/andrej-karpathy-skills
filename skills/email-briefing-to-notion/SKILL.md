## 0-1. 주말 실행 금지 확인

## 0-2. 월요일 주간 요약 분기

get_current_korean_time으로 확인한 요일이 **월요일**이면 아래 주간 요약 흐름을 먼저 실행한다.
월요일이 아니면 즉시 Step 0-3으로 건너뛴다.

### 이전 주 폴더 탐색

주간 요약을 넣을 이전 주 폴더를 먼저 확인한다 (Step 0-3 로직과 동일, 이전 주 기준).

- `prev_monday_` = today_(월요일) - 7일
- `prev_month_folder_title_` = `N월 이메일 브리핑` (prev_monday_ 기준 월)
- `prev_week_folder_title_` = Step 0-3 방식으로 계산 (prev_monday_ 기준)
- 루트 하위에서 `prev_month_folder_title_` 탐색 → 없으면 생성 → `prev_month_folder_id_`
- `prev_month_folder_id_` 하위에서 `prev_week_folder_title_` 탐색 → 없으면 생성 → `prev_week_folder_id_`

### 주차 계산
- 지난주 범위: `prev_monday_` ~ `prev_monday_` + 6일(전주 일요일)
- 페이지 제목: `N주차 이메일요약`
  - N주차 = `prev_week_folder_title_`의 N 값과 동일
  - 예: 지난주가 6월 첫째 주 → `1주차 이메일요약`
  - 월 경계를 넘는 경우(예: 지난주 월요일이 5월, 일요일이 6월) → prev_monday_의 월 기준 N 산정

### 중복 확인
`prev_week_folder_id_` 하위에 동일 제목(`N주차 이메일요약`)이 이미 존재하면:
- 새 페이지를 만들지 않는다
- 기존 페이지 하단에 `--- 추가 갱신 (HH:MM) ---` 섹션으로 append

존재하지 않으면 아래 지난주 페이지 수집으로 진행.

### 지난주 일일 페이지 수집
- `prev_week_folder_id_` 하위 페이지 목록 조회 (없으면 루트 하위에서도 검색)
- 제목 패턴 `YYYY.MM.DD (요일)` 중 지난주 7일(월~일)에 해당하는 페이지를 수집
- 각 페이지를 `notion-fetch`로 읽어 P1~P4 건수 및 액션 아이템 추출
- 페이지가 없는 날짜는 `-` 표시

### 주간 요약 페이지 생성
- **위치**: 이전 주 폴더(`prev_week_folder_id_`) 하위
- **제목**: `N주차 이메일요약`
- **아이콘**: 📊


### 주간 요약 완료 후
주간 요약 페이지 생성이 완료되면 Step 0-3으로 진행하여 **오늘(월요일) 일일 브리핑도 함께 실행**한다. (월요일은 주말 종료 대상에서 제외되므로 일일 브리핑도 정상 실행)

### 주간 요약 오류 처리

## 0-3. 월별·주별 폴더 준비

일일 브리핑을 넣을 월 폴더와 주 폴더를 확인하고, 없으면 생성한다.

### 변수 계산

| 변수 | 계산 방법 |
|------|----------|
| `month_folder_title_` | `N월 이메일 브리핑` (today_ 기준 월, N = 월 숫자) |
| `week_monday_` | today_ 가 속한 주의 월요일. 단, 해당 월요일이 today_ 와 다른 달이면 today_ 달의 1일 |
| `week_sunday_` | 해당 주의 일요일. 단, 월말을 넘으면 해당 달의 마지막 날 |
| `week_n_` | today_ 달 기준 주 번호 (달의 1일을 포함하는 주 = 1주차, 이후 월요일마다 +1) |
| `week_folder_title_` | `N주차 (MM.DD~MM.DD)` — week_n_, week_monday_, week_sunday_ 사용 |
| `target_parent_id_` | 일일 브리핑 및 중복 확인에 사용할 주 폴더 ID |

**주차(N) 계산 예시**
- 6/1(월) → `1주차 (06.01~06.07)`
- 6/8(월) → `2주차 (06.08~06.14)`
- 6/4(목), 이 주 월요일 6/1 → `1주차 (06.01~06.07)`
- 6/3(수), 이 주 월요일 5/28(이전 달) → week_monday_=6/1로 대체 → `1주차 (06.01~06.07)`

### 월 폴더 확인·생성

1. 루트 페이지(`3643e986-a942-812e-b4e9-dca08f857e86`) notion-fetch → 하위 페이지 중 `month_folder_title_` 탐색
2. 존재하면 → `month_folder_id_` 기록
3. 없으면 → notion-create-pages (제목: `month_folder_title_`, 아이콘: 📅, 내용: `"N월 전체 이메일 브리핑 보관 공간"`, 부모: 루트) → `month_folder_id_` 기록

### 주 폴더 확인·생성

1. `month_folder_id_` notion-fetch → 하위 페이지 중 `week_folder_title_` 탐색
2. 존재하면 → `target_parent_id_` 기록
3. 없으면 → notion-create-pages (제목: `week_folder_title_`, 아이콘: 📋, 내용: `"기간 브리핑"`, 부모: `month_folder_id_`) → `target_parent_id_` 기록

주 폴더(`target_parent_id_`) 하위에 `today_` 제목 페이지가 이미 존재하면:

- 기존 페이지 하단에 `--- 추가 브리핑 (HH:MM ) ---` 섹션으로 append
- 전날 노션 페이지를 확인하여 이어지는 내용이 있으면 연관 표시를 한다.

존재하지 않으면 Step 2로 진행.

## 2. Gmail 이메일 수집

### 검색 쿼리
```
in:inbox -is:spam -in:draft -in:sent -label:[Notion]
after:start_date_ before:today_
```
- `today_` = 브리핑 대상 날짜 (KST 기준, 실행일과 다를 수 있음)
- `start_date_` = 아래 날짜 범위 규칙으로 결정
- pageSize: 50
- `-label:[Notion]` = 이미 처리된 이메일 제외 (중복 방지)

### 날짜 범위 결정 규칙

**[규칙 1] 월요일 예외 (최우선 적용)**
요일이 월요일이면:
- `start_date_` = 당일(월요일) -3일인 **금요일**
- `before:today_` = **당일(월요일)** 유지 — 월요일 당일 이메일 미포함
- 단, 금요일도 휴일이면 규칙 2를 이어서 적용

**[규칙 2] 휴일 연장 (화~금, 또는 규칙 1 적용 후 추가 확장)**
`start_date_`가 휴일(토·일 또는 한국 법정 공휴일)이면:
- `start_date_`를 1일 더 앞당긴다 (→ 전전날 06:30부터 포함)
- 앞당긴 날도 휴일이면 계속 반복 → 평일에 도달할 때까지 앞당김

> 예 1) 화요일 실행, 어제(월)=공휴일 → `start_date_`=일요일 → `after:일 before:화` (일·월 이메일 포함)
> 예 2) 화요일 실행, 어제(월)=공휴일·그제(일)=일요일 → `start_date_`=토요일 → `after:토 before:화` (토·일·월 포함)
> 예 3) 월요일 실행, 지난 금요일이 공휴일 → 규칙 1로 `start_date_`=금요일 → 규칙 2로 목요일로 앞당김

### 조회 전략 (토큰 절약)
1. `search_threads` — 제목·발신자·스니펫 전체 수집
2. 스니펫+제목으로 1차 분류 (Step 3)
3. **P1·P2만** `get_thread`로 본문 전체 조회
4. P3·P4는 스니펫+제목으로만 요약

### 컨텍스트 초과 시
P1 → P2 → P3 → P4 순으로 우선 처리하고, Notion 페이지 최상단에 표기:
```
⚠️ 컨텍스트 제한 — 총 N건 중 M건만 처리됨
```

모호한 경우 더 높은 우선순위로 분류한다.

### 🔴 P1 — 긴급 사항 (Critical)
- TO에 `han@solardin.com`, `한이현` 직접 포함

- ❌ 루트 페이지(이메일 브리핑) 계층 외부에 페이지 생성 (월·주 폴더는 루트 계층 내부이므로 허용)
- ❌ 이메일 내용 외부 시스템 전달
- ❌ 주간 요약 생성 시 Gmail 이메일 레이블 재조작 (일일 브리핑에서 이미 처리됨)

## 오류 처리

| 상황 | 동작 |
